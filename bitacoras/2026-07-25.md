## Qué entendí bien

- Si uno desea saber quién fue el resposable de cada cambio en un archivo del proyecto, puede usar `git blame <archivo>`. Esto mostrará una lista con los _commits_ en los que el archivo estuvo relacionado, asociando cada conjunto de cambios con el autor y la hora en la que se declaró cada _commit_. Si el usuario quisiera visualizar esta secuencia de cambios, pero solo apartir de cierto _commit_, puede entregar su _hash_ como argumento `git blame <hash> -- <archivo>`
- Para buscar cierto contenido dentro de todos los archivos rastreados por Git, ya sea una palabara o una frase, se puede usar el comando `git grep "<contenido>"`.
  - `-i`: por defecto, `git grep` es _case-sensitive_. Con esa bandera no
  - `-n`: con esta bandera, el comando, además de mostar las coincidencias, mostrará en qué línea del archivo encontró esa coincidencia
  - `-l`: en lugar de mostrar todas las líneas en las que encontró coincidencias, con esta bandera solo mostrará el archivo donde haya encontrado la coincidencia
- Existen un par de banderas de `git log` que también permiten la búsqueda de cambios o contenido en específico dentro del repositorio, a saber:
  - `--grep="<contenido>"`: filtra la lista de _commits_ con base en si el contenido dado como argumento aparece o no en el mensaje del _commit_
  - `-S "<contenido>"`: filtra la lista de los _commits_ con base en el número de veces que aparece `<contenido>`, si el número de ocurrencias cambió (aumentó o disminuyó), entonces el _commit_ se muestra
  - `-G "<contenido>"`: filtra la lista de los _commits_ con base en el _diff_, si `<contenido>` aparece en él (es decir, `<contenido>` fue eliminado o agregado en ese commit), entonces se muestra el _commit_
  - `-p`: agrega el _diff_ completo a la lista de _commits_ mostrados
- Como ayuda para encontrar el _commit_ en donde se haya agregado un conflicto en un archivo rastreado, se puede usar el comando `git bisect`. Este comando no corrije el error, solo ayuda a encontrar en qué _commit_ se introdujo. Su uso es según el siguiente flujo:
  - Iniciar el algoritmo con `git bisect start`
  - Luego de iniciar el algoritmo, se le da a Git un _commit_ en donde esté presente el error (usualmente el _commit_ desde donde se ejecuta `git bisect`) con `git bisect bad <hash-del-commit>` y al menos un _commit_ en donde no esté presente el error con `git bisect good <hash-del-commit>`.
  - Entonces Git propone un punto medio en donde pudo haberse introducido el error. Una vez calculado, Git hace que _HEAD_ apunte a ese _commit_, y entonces el usuario debe determinar si esa versión contiene el error. Entonces puede ocurrir uno de dos casos:
    1. Si el conflicto no se encuentra en esa versión, ejecuta `git bisect good`
    2. Si el conflicto sí se encuentra en esa versión, ejecuta `git bisect bad`
  - Para cualquiera de los dos casos, el algoritmo vuelve al punto tres hasta que Git determina cuál es el _commit_ en donde se introdujo el error.
  - Al terminar, `git bisect reset` te devuelve al estado (rama o commit) en el que estabas cuando ejecutaste por primera vez `git bisect start`.
- Por defecto, el comando `git config` ayuda a cambiar la configuración con la que se quiere trabajar en un solo repositorio, como el nombre y correo del usario, qué editro de texto quiere utilizar, entre otros. Con la bandera `--global`, estos cambios son generales. Se puede consultar los cambios locales en la ruta `./.git/config` y los cambios globales en `C:/Users/<nombre-de-usuario>/.gitconfig`
- Existen comandos que son más utilizados que otros, si estos comandos luego son demasiado largos se recomienda el uso de alias para optimizar el tiempo. Estos alias se configuran como `git config --global alias.<alias-del-comando> "<comando>"`. Al ser una configuración con la bandera `--global`, estos alias pueden consultarse en la ruta `C:/Users/<nombre-de-usuario>/.gitconfig`
- Para ignorar elementos dentro de un repositorio se usa un archivo de texto llamado `.gitignore`. Este archivo no se genera por automáticamente al iniciar un repositorio, sino que debe ser creado por el usuario. Para ignorar un elemento solo hace falta añadirlo en este documento:
  - `<directorio>/` para ignorar todos los archivos dentro de un directorio. Si el directorio comienza con un punto, este también se incluye `.<directorio>/`
  - `*.<terminacion>` para ignorar todos los archivos cuya terminación sea `<terminacion>`
  - `<nombre-del-archivi>` para ignorar un archivo en específico
